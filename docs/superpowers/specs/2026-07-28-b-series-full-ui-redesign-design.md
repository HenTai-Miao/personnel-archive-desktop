# B 系列全客户端 UI 改版设计

**日期：** 2026-07-28  
**目标副本：** `personnel-archive-desktop-b`  
**参考稿：** `/tmp/brainstorm-58298-1785208776/content/full-page-directions.html` 中的“B 卷宗检阅桌”  
**改版范围：** 登录页及全部已实现业务页

## 1. 目标与边界

在当前项目下创建 `personnel-archive-desktop-b`，保留现有 `personnel-archive-desktop` 不变。新副本把 B 系列从单页方向稿扩展为完整客户端设计系统：登录、应用外壳、人员档案、完整详情、家庭成员查询、批量导入、导入历史、文件夹设置及所有弹窗和状态均使用同一套颜色、排版、间距和卷宗布局语言。

本次是客户端视觉与信息架构改版，不改后端、数据库、OpenAPI、IPC 权限边界或既有业务规则。以下能力必须保留：认证和会话过期处理、角色控制、20 条固定分页、批量 ZIP 导出、单份 Excel 下载打开、敏感字段逐项显示与清理、照片鉴权加载与 Object URL 回收、原因必填的软删除、手动/自动导入、重复决定、导入历史及安全本地归档。

## 2. 方案比较与决定

### 方案 A：逐页机械复制 B 三栏

所有页面均固定使用“左索引—中内容—右目录”。优点是外观最一致；缺点是登录、家庭查询和批量导入没有天然的卷宗章节，强行三栏会浪费空间并削弱任务效率。

### 方案 B：只替换颜色和圆角

保留现有 DOM 与交互，仅把 CSS 改成 B 配色。改动小，但无法兑现“重新设计 UI 布局”，人员目录仍会是现有表格加抽屉，而不是参考稿的卷宗检阅桌。

### 方案 C：统一 B 设计系统，按业务适配布局（采用）

保留 B 的顶栏、业务目录、索引栏、档案纸页、章节目录和状态语言，并按每个页面的真实任务组合。人员档案忠实使用三栏；查询、导入和设置使用相同构件形成适合任务的双栏或三栏布局。该方案既保持明确的 B 系列识别度，又不牺牲既有业务能力。

## 3. 视觉系统

### 3.1 颜色令牌

直接继承参考稿核心颜色，不引入第二套主题：

- `Dossier blue #034ED6`：主操作、当前导航、焦点和选中记录。
- `Deep blue #0342B8`：主操作悬停和按下状态。
- `Paper white #FFFFFF`：应用底色、卷宗纸页和面板。
- `Blue wash #F4F8FF`：选中行、弱提示和顶部环境光晕。
- `Archive ink #141928`：标题及主要正文。
- `Archive gray #5D6579 / #6B7489 / #E8EAF0`：辅助文字、弱文字和分隔线。
- 状态色保留参考稿的成功 `#15803D`、警告 `#A85C00`、危险 `#C93438`，仅表达真实业务状态。

页面不使用大面积深色驾驶舱、装饰性渐变卡片或虚构统计数据。顶部只保留 B 稿中极轻的蓝/紫/青径向光晕，内容区保持白色档案纸感。

### 3.2 字体与信息层级

- 中文正文和标题：`PingFang SC`、`Microsoft YaHei UI`、`Microsoft YaHei`、系统无衬线后备。
- 档案编号、角色、时间和英文眉题：`ui-monospace`、`Cascadia Mono`、`SFMono-Regular`、`Consolas`。
- 页面标题 28–30px，档案姓名 28px，区块标题 15px，正文 13px，标签与说明 11–12px。
- 英文眉题只用于表达真实页面语义，例如 `DOSSIER READING DESK · 卷宗检阅`；不为普通卡片添加无意义编号。

### 3.3 形状、间距与动态

- 顶栏 60px，业务目录 252px；卡片圆角 13px，字段 10px，按钮 9px，标签 7px。
- 卡片主要依靠 `#E8EAF0` 细边框分层，阴影只用于弹窗和浮层。
- 交互动画集中在选中记录、页面状态和章节定位，持续 120–180ms。
- `prefers-reduced-motion: reduce` 下关闭平滑滚动、位移和过渡。
- 所有键盘焦点使用 2px 钴蓝轮廓，不能仅以颜色表示当前项。

### 3.4 识别性元素

整套客户端的记忆点是“活卷宗纸页”：左侧索引选择一份档案，中央纸页按工作簿顺序连续展开，右侧目录跟随当前章节。其他业务页沿用“索引栏＋纸页”的结构，但不伪装成人员档案。

自查后舍弃了通用后台常见的指标卡、深色驾驶舱和大面积渐变；这些元素与本系统的档案检阅任务无关。保留的顶部光晕、等宽编号和连续纸页均来自参考 B 稿及人员档案业务本身。

```text
├────── 252px 业务目录 ──────┬───────────────────────────────────────┤
│ 人员档案                    │ 当前路由工作区                        │
│ 家庭成员查询                │                                       │
│ 批量导入（按角色显示）      │                                       │
│                             │                                       │
│ 会话与敏感字段安全提示      │                                       │
└────────────────────────────┴───────────────────────────────────────┘
```

- 顶栏增加与参考稿一致的任务分组：`卷宗检阅` 对应人员档案、详情和家庭查询；`批处理` 对应导入及文件夹设置。
- 状态胶囊只显示客户端确知的信息，使用“安全会话已建立”，不虚构“数据服务正常”健康检查。
- 用户区显示真实 display name、主角色和退出操作；角色来自现有认证状态。
- 左侧导航权限规则不变。文件夹设置入口继续保持隐藏，但路由页面仍完成 B 系列改版。

## 5. 页面设计

### 5.1 登录页

登录页不套用登录后业务目录，而是使用同一颜色、字体和卷宗构件形成左右两区：左侧为系统身份、用途和安全说明，右侧为紧凑登录纸页。页面不展示虚构人数、导入量或服务健康状态。

用户名、密码、恢复会话、登录失败和过期提示保持现有逻辑。1080px 最小宽度下仍为双区；较低高度时允许页面纵向滚动，防止表单被裁切。

### 5.2 人员档案目录

```text
┌ 页面标题、批量导出、打开 Excel、更多操作 ──────────────────────────┐
├──── 286px 卷宗索引 ────┬────────── 完整档案纸页 ─────────┬─ 238px ─┤
│ 搜索 / 展开筛选         │ 人员抬头、照片、状态、操作      │ 卷宗目录 │
│ □ 人员记录              │ 基本情况                       │ 当前章节 │
│ □ 人员记录              │ 现任职务                       │ 章节跳转 │
│ □ 人员记录              │ 教育、经历、奖惩、家庭、申报   │          │
│ 20 条分页                │                               │          │
└────────────────────────┴────────────────────────────────┴──────────┘
```

- 当前页 20 条记录进入左侧索引，人员编号使用等宽字体。姓名、编号快速搜索常驻；单位/部门等完整筛选在索引栏内展开，仍调用现有查询参数。
- 每条记录同时具有“检阅选中”和“批量勾选”两种独立状态。点击记录加载完整详情与照片；勾选框只影响批量 ZIP 导出。
- 初次进入或翻页后不自动请求第一份详情，避免无用户动作的照片查看审计。中央显示明确的“请选择卷宗”空状态。
- 中央纸页复用完整详情的所有工作簿区块。身份证和手机号默认遮罩，逐字段显示、失败回退和离开清理规则不变。
- 单份导出、打开 Excel 和角色允许的删除放在当前卷宗抬头操作区；删除仍使用现有原因弹窗和刷新逻辑。
- 现有可调整抽屉及其分隔条在 B 副本中移除，由三栏检阅桌取代。

### 5.3 独立完整详情

`/persons/:personId` 保留，供家庭成员查询和直接路由进入。页面使用“中央档案纸页＋右侧章节目录”，顶部提供返回、下载并打开 Excel。家庭成员查询传入的匹配成员继续定位并高亮；照片和敏感字段生命周期不变。

### 5.4 家庭成员查询

左侧为 286px 查询与匹配索引，包含输入框、搜索按钮、总数和 20 条分页；右侧为结果纸页，按匹配关系完整展示人员、单位/部门、职务、职称/技能及“查看档案”。选择结果只高亮和展示匹配摘要，不自动拉取照片或敏感数据。无查询、无结果、加载失败分别使用有下一步指引的 B 系列空状态。

### 5.5 批量导入与导入历史

页面采用“左侧文件队列＋中央处理纸页＋右侧批次目录”：

- 左侧保留选择文件、自动扫描来源、队列标签和本地 20 条分页。
- 中央展示当前批次逐文件状态、重复决定入口、本地归档状态和本地 20 条分页。
- 右侧目录在“待处理文件、当前批次、永久历史”之间定位，并显示来自真实当前状态的数量，不创建指标或新数据源。
- 永久导入历史继续按服务端 20 条分页，放在中央纸页的独立区块，不压缩成无法阅读的窄栏。
- 重复档案、覆盖二次确认、陈旧决定和归档重试弹窗全部改为 B 系列样式，默认 `SKIP` 及所有安全规则不变。

### 5.6 文件夹设置

隐藏路由仍需完整改版。待上传目录、成功归档目录、扫描状态和保存操作放入连续设置纸页，右侧目录用于定位“待上传、成功归档、安全规则”。不恢复业务目录入口，不改变 IPC 或文件移动策略。

### 5.7 共用状态与弹窗

加载骨架、空状态、网络错误、权限不足、会话过期、成功提示、删除弹窗和重复决定弹窗统一使用 B 令牌。错误信息必须说明发生了什么以及下一步操作；不能用装饰性文案代替稳定错误码映射。

## 6. 响应式规则

- 基准验收尺寸为 1440×960；应用继续支持 1080px 最小宽度。
- 工作区大于 1320px：人员档案显示完整三栏。
- 工作区 1080–1320px：隐藏右侧章节目录，把章节导航变为中央纸页顶部的粘性横向导航；左索引缩至 240px。
- 家庭查询和设置在窄工作区转为单主栏，索引/查询区置于内容上方。
- 表格和长字段允许自身横向滚动，不能撑破应用外壳。
- 所有页面对低高度窗口保留可滚动内容和可见分页，不把操作按钮固定到视口外。

## 7. 组件与样式架构

- 新建并只加载 `src/renderer/src/styles/dossier-reading-desk/`，按 `theme`、`shell`、`navigation`、`records`、`detail`、`workflow`、`pagination`、`auth`、`dialogs` 分责。
- 保留旧 `archive-workbench` 文件作为未加载的历史视觉层；`styles.css` 只能加载新的 B 系列入口，避免级联叠加。
- 抽取共享页面抬头、索引面板和章节目录组件，只有两个以上页面使用时才共享，避免为单页样式建立抽象。
- 抽取可复用的完整卷宗读取组件及其照片/敏感字段生命周期，使人员目录中央纸页和独立详情页使用同一实现。
- Pinia store、API 层、Zod schema、Electron main/preload 和 IPC contract 保持权威边界，不把 HTTP 或 Node 能力下放到页面组件。

## 8. 数据流与安全

1. 人员目录继续通过现有 store 请求服务端分页摘要。
2. 用户点击索引记录后才请求完整详情；存在照片时再走鉴权照片端点。
3. 用户明确点击“显示”后才请求单个敏感字段，并在隐藏、换人、换路由或卸载时清理。
4. 批量勾选继续只保存 Person ID 字符串并交给现有 ZIP 导出流程。
5. 删除、导入决定和文件移动继续经过现有 API/IPC 边界；视觉重排不能改变授权或事务语义。
6. 页面不新增人员数据本地缓存、健康检查轮询、日志载荷或虚构业务数据。

## 9. 副本与文档策略

- 使用当前 `personnel-archive-desktop` 工作树作为源，保留现有未提交的 `.gitignore` 中 `output/` 规则。
- 通过 `git clone --no-hardlinks` 复制历史，再覆盖当前工作树内容，使 `personnel-archive-desktop-b` 拥有独立 Git 元数据且保留源目录未提交内容；创建 `codex/b-series-redesign` 专用分支，不在源目录或主分支提交。
- 不复制 `node_modules`、`out`、`release`、`output`、`.worktrees` 和编辑器缓存；依赖使用现有锁文件重新安装或通过包管理器恢复。
- 不修改原桌面端源代码。根 `AGENTS.md` 和 `CODE_GUIDE.md` 只增加 B 副本的定位及实际新结构说明，不把它误写成当前生产启动路径。
- 副本内 `AGENTS.md` 更新为 B 系列当前状态；若组件或样式路径改变，同步更新根 `CODE_GUIDE.md`。

## 10. 测试与验收

### 自动化

- 先为新的 AppShell 结构、人员索引/检阅状态、独立批量选择、详情生命周期、查询布局和导入布局写失败测试，再实现。
- 更新依赖旧抽屉结构和 `03 卷宗联动台` 文案的测试；业务行为断言继续保留。
- 保留所有 API、分页、删除、导入、IPC 和敏感字段测试。
- 完成后依次运行 `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build`。
- `pnpm test:e2e` 仅在普通 macOS 桌面会话或 Windows CI 运行；Codex Seatbelt 环境继续在创建 Electron 进程前失败。

### 视觉验收

- 在 1440×960 检查登录、人员空状态、人员检阅、完整详情、家庭查询结果、批量导入结果及弹窗。
- 在 1080px 最小宽度验证右目录折叠、表格操作、分页、弹窗及长文本不被裁切。
- 检查键盘导航、焦点可见性、遮罩值、加载/失败/空状态和 reduced-motion。
- 对照参考 B 稿确认顶栏、业务目录、颜色、间距、索引面板、连续纸页和章节目录具有同一视觉语言，同时所有内容均来自真实应用状态。

## 11. 完成标准

只有在原桌面端未被改动、B 副本可独立安装依赖、全部授权业务流保持、自动化验证通过、关键页面截图与 B 稿一致、窄窗口可用，并同步更新副本 `AGENTS.md` 与根 `CODE_GUIDE.md` 后，才可声明改版完成。
